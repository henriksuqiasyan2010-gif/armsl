# Правила проекта

Школьный ML-проект: распознавание 12–22 динамических жестов армянского
жестового языка в реальном времени через веб-камеру. CPU-only ноутбук,
автор — новичок в ML, весь код проходит через собеседование с автором
(объяснение построчно) перед тем, как считается принятым.

## Стек и версии — жёстко

- Python 3.9–3.12 (mediapipe официально не поддерживает 3.13+, ставок
  на будущее не делаем)
- numpy: используй версию, совместимую с установленной версией
  mediapipe (актуальные mediapipe с numpy 2.x работают)
- MediaPipe Tasks API только: mediapipe.tasks.python.vision.HandLandmarker.
  Модуль mediapipe.solutions.hands НЕ существует в актуальных версиях —
  никогда не используй его, даже как fallback или в комментариях-примерах.
- Модель детекции рук — локальный файл models/hand_landmarker.task,
  никаких скачиваний во время выполнения программы.
- GRU через tensorflow/keras для классификации, не LSTM (если не оговорено
  отдельно) — GRU легче на CPU.
- Tkinter для GUI (входит в стандартную библиотеку, отдельно не ставить).
- Все константы — только в src/config.py. Никаких магических чисел
  (30, 60, 128, пороги) напрямую в других файлах.

## Контракт данных — не менять без согласования

- Один образец жеста = np.float32 массив формы (60, 128).
  60 = число кадров в окне (~2–4 с при типичном FPS вебкамеры).
  128 = 2 руки × 21 точка × (x, y, z) [126] + 2 флага видимости руки.
- Порядок в векторе кадра фиксирован по handedness: первые 63 числа —
  левая рука, следующие 63 — правая. Если порядок нарушить —
  модель будет обучаться на шуме. Это самое частое место ошибки,
  проверяй тестом на каждую реализацию features.py.
- Если рука не найдена в кадре — соответствующие 63 числа = 0.0,
  флаг видимости = 0. Кадр не пропускается, окно всегда ровно 60 кадров.
- Файлы датасета: data/raw/{label}/{person}_{session}_{idx}.npy
- Метаданные: data/meta.csv, колонки:
  file,label,person,session,date,lighting,background,distance_m,notes
- models/labels.json — упорядоченный список классов; индекс класса
  в этом списке = индекс выхода softmax модели. Модель и labels.json
  всегда обновляются вместе, никогда по отдельности.

## Разбиение данных — критично для честности результатов

- Никогда не используй случайный (random) train/val split.
- Разбиение — только по группам person + session: вся сессия одного
  человека целиком уходит либо в train, либо в val.
- Причина: случайный split даёт утечку данных (соседние кадры одного
  движения похожи), что даёт фальшиво высокую точность и провал в
  реальном времени. Если пишешь dataset.py — добавь тест, что
  пересечение групп train и val пусто.

## Сигнатуры модулей (см. functional requirements)

landmarks.py
  class HandTracker:
      def detect(frame_bgr, timestamp_ms) -> list[HandResult]

features.py
  def frame_to_vector(hands: list[HandResult]) -> np.ndarray   # (128,)
  def normalize_window(window: np.ndarray) -> np.ndarray       # (60,128)->(60,128)

dataset.py
  def load_dataset(data_dir) -> tuple[np.ndarray, np.ndarray, np.ndarray]  # X, y, groups
  def split_by_group(X, y, groups, val_groups) -> tuple
  def augment(window, seed) -> np.ndarray

predictor.py
  class RealtimePredictor:
      def push(vector: np.ndarray) -> None
      def result() -> tuple[str | None, float, list[tuple[str, float]]]

Не меняй эти сигнатуры без явного запроса — на них завязаны другие модули.

## Как работать над кодом

1. Один модуль — одна задача. Не пиши сразу несколько файлов из src/,
   если явно не попросили.
2. Перед кодом — сначала план в 3–5 пунктов, что собираешься делать.
   Дай мне подтвердить, потом пиши код.
3. Каждый модуль сопровождается тестом в tests/ на его ключевую логику
   (особенно: порядок рук, нормализация, длина окна, разбиение по группам,
   сглаживание предсказаний).
4. Комментарии и docstring — на русском. Я учусь, мне важно понимать код,
   а не просто получить рабочий результат.
5. После любого готового модуля — короткое объяснение простыми словами:
   что делает файл, почему тут именно такое решение.
6. Не добавляй зависимости, которых нет в requirements.txt, без вопроса.
7. Не трогай уже принятые и закоммиченные модули без явной просьбы.

## Что вне рамок проекта — не предлагать

Распознавание фраз/грамматики, мимика, дактиль, веб/мобильная версия,
несколько человек в кадре одновременно, облачные сервисы и базы данных.
Если кажется, что задаче не хватает одного из этого — сначала спроси,
а не добавляй сам.
